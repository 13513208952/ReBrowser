- ID：`rebrowser-root-2897220b1306695b`
- 角色／工程等级：`ROOT`／10
- 算法：ECDSA P-256／SHA-256
- SPKI SHA-256：`2897220b1306695b955d7d8d91c9d34f23d342e9ae5260b68619363b02fd2f11`

[公开配置与持钥样本](../planning/geckoview-v2/records/admin-root-public-provisioning.json)仅含公钥和独立登记域的公开验签样本。`CompiledPrincipals`固定编入该公钥，仍拒绝公开测试密钥。Root可在当前已注册普通动作范围内委托低于高级边界的权限；不是允许运行时新增高级身份。

私钥采用加密PKCS8保存在仓库外，随机口令置于另一受限位置；二者均在同一主机，权限0700／0600。**这不等于抵御整机失陷或已经完成离线托管。**独立离线副本和机主恢复交接尚未完成。不要自动重新生成、替换此Root，也不要把私钥、口令或含私密设备信息的记录加入仓库。Root变更属于来源连续性变化，不是普通配置覆盖。

配置管理员公钥不等于生成APK签名密钥、设备安装密钥，不等于来源已接受、旧数据解锁、已取得机主同意或管理员命令已经生效。

## 设备名单不是唯一准入入口

对于有效、未禁用且等级与作用域充分的管理员：

1. 普通动作不要求设备一律在名单内。
2. 被标为最高危的动作，有适用且经持钥验证的编译设备名单例外时，可走相应免确认路径。
3. **没有名单例外时，仍允许“有效管理员密钥＋真实机主同意／系统认证”路径**，授权限定动作、目标、范围及期限。Root也不能在名单外静默免除该认证。
4. 机主认证不能把低权限凭据变成Root，也不替代Android／官网自身强制权限、请求防重放及来源数据保护。

`DeviceWhitelist`明确不是全局允许名单；现有普通动作准入已有“零已登记设备仍可凭合法管理员身份进行预留”的实际HOST回归。`OwnerGrantStore`提供本机同意和系统认证封装，但最高危动作、真实当前权限头及统一调度器的完整接线仍待完成；不得把上述规则宣称为已经实机可用的完整控制系统。

## 首个已连接设备（R56被动观察）

已按机主授权被动读取唯一ADB设备的必要系统与本项目包信息，详细型号、序列号等仅留仓库外。观察时未安装正式`io.github.rebrowser`或开发包，因而尚无可获取的v2安装密钥公钥。

[登记状态](../planning/geckoview-v2/records/device-enrollment-status.json)将其记录为Root名单的机主已批准候选，**不是已激活名单项**。不能把ADB序列号、型号、UID、APK证书或另一测试包的密钥替代正式安装持钥证明。

后续须在最终包名及正式APK签名下完成受控安装登记，取得该安装的Android Keystore公钥、真实新鲜持钥证明和所需机主登记凭据，再编入公钥／归属及最小收据绑定。同包同签名更新才能保持原安装密钥；没有默认自动登记所有连接设备的行为。

R56阶段未安装或启动应用、唤醒或解锁设备、弹机主认证、生成设备密钥、读取旧应用数据或激活名单豁免。
