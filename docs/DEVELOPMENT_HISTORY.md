### v1.0.0 首个正式版

主仓库原地更名为 ReBrowser，提交／标签／历史 Releases 保留；软件以 ReBrowser 为主，ReOutlook 为同 APK 的子软件。最终三个设置页为常规、隔离与权限、应用管理，按机主追加需求删除个性化页，风味决定未显式选择的默认背景，已保存的背景／近期偏好继续保留。新增原生缺能力回退和固定管理员环境／模式接口。README 整篇改为用户入口，用户指南和开发参考拆分。

本轮两版各 146 JVM、39 Node、9 CLI、3 打包检查通过；最终包核对签名、对齐、无损内容和网络政策，体积分布见[v1.0.0 发布记录](releases/v1.0.0.md)。真机同签名覆盖升级及最终两风味安装，持久测试 Profile／Cookie 和固定设置保留；邮件入口隐藏／进入／恢复、三页及默认应用入口验证通过。原生管理员任务与设置页重用路由的两个问题经真机复现、修正并回归；测试样本与其历史单独清理，最新默认浏览器选择未变。

能力不足／无 provider 回退为 JVM 模拟；没有扩展成完整设备或邮件数据迁移覆盖声明。`.1` 操作未执行，继续由机主自行测试。

### 对架构现状的理解

现有 Controller 划分是连续版本逐步形成的，并非尚未开始整理的单体 Activity。历史说明强调明确状态所有者、窄接口，以及避免引入事件总线或泛化控制器抽象。

v0.3.1 至 v0.3.5 的发布说明记录了不改变持久化格式和既有功能的重构目标，以及各阶段的真机检查。以后是否继续拆分、引入框架或调整格式，应按实际需求讨论，而不是仅凭文件行数决定。

## 已有验证及其范围

### 邮件同步与迁移

除了公开仓库的测试，临时目录还保留：

- `test_capture_sync.js`：模拟网页桥与服务响应，检查 HTTP／服务错误、完整正文、缺失正文、GetItem 补取、草稿排除、截断正文、syncToken 与预期写入数量，以及模拟长会话从 20 项扩展到 30 项。它读取临时目录中的 `capture.js` 快照，不自动绑定当前 Java 源码。
- `test_account_migration.py`：在独立测试数据库中构造旧结构，执行迁移 SQL，检查完整性、外键、记录保留及首次账号接管。它不是直接调用 Android MailDatabase 的迁移测试，并会重建自己的测试文件；本轮未执行。

因此，邮件侧并非没有测试资产，但这些脚本尚未纳入当前仓库的常规测试入口。模拟长会话和迁移 SQL 检查，也不等于真实长会话、第二真实账号或 Android 数据库生命周期已经端到端覆盖。

公开架构文档另记录过使用 612 封历史邮件和 579 个检查点验证 v2 → v4 无损迁移；本轮没有打开对应真实邮件数据。

## 历史选择的上下文

- **Debug 证书**：当时用于维持测试设备原地升级连续性，并未宣称正式生产签名。
- **下载请求位置只保存 origin**：用于避免持久化带令牌 URL，代价是进程重启后部分请求不能直接重试。
- **拒绝 POST／未知上下文下载**：源于 WebView 不提供完整原始请求信息，而不是遗忘实现普通下载。
- **系统 WebView 与命名 Profile**：是当前实现基础；完整浏览器内核属于曾提出的候选方向，尚非已确定迁移任务。
- **Room、普通用户备份、无痕环境等**：历史文档中列为后续候选，不能据此认定项目所有者已批准实施。

这些背景解释当前取舍，不代替项目所有者对后续目的和方案的判断。
