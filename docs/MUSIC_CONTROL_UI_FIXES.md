# 音乐控件外观修复：v1.0.4 累计开发记录

继[启动优化](MUSIC_STARTUP_OPTIMIZATION.md)后，机主另行指出两项不同范围的问题：旧平板系统喜欢图标正常，而 Android 16 手机上的图标是星形；网页暂停态的播放按钮则在各设备上都呈椭圆。不能混为同一平台问题，也不能把会话状态检查当成完整界面验收。

该修正纳入[v1.0.4](releases/v1.0.4.md)。以下记录原签名、不可调试的 `1.0.4-dev-controls1` 私有全量预览，不把其截图及数字冒充最终APK专项复验；旧标签和资产不替换。

后续[完整播放页与歌词开发](MUSIC_EXPANDED_PLAYER_AND_LYRICS.md)另行补充展开页的适配和心形光学细化；下文的 controls1 安装／截图及计数保留为该候选的历史证据，不冒充后续新轮廓或完整页通过。

## Android 16 系统喜欢图标

当前手机只读会话检查显示：评分类型与用户评分类型都为 HEART，当前状态为未喜欢，但应用提供的 `toggle-like` 自定义动作图标是固定的 `android:drawable/btn_star_big_on`。喜欢状态并未丢失；评分心形与自定义动作星形不一致。本机显示星形，不能据此断言平板也走同一绘制路径或是 Android 16 系统本身画错。

`ReBrowserMusicSystemIcons` 仅在 API 36 及以上为自定义动作和通知动作提供空心/实心心形，随已经确认的 `snapshot.liked` 选择。API 35 及以下保持原图标和评分路径不变，不改机主报告正常的旧平板分支。`RATING_HEART`、`ACTION_SET_RATING`、固定动作名称、原网页喜欢操作、nonce 和会话生命周期均不改变。

安装后本机只读状态仍为 HEART/未喜欢，操作掩码不变，图标来源已变为应用的空心心形资源；系统媒体卡片截图也确认空心心形。没有点击喜欢或取消喜欢来构造账号基线。实心资源及状态映射通过 JVM/资源加载测试，**未实际改变真实账号来完成实心态联动验收**。旧平板没有重新连接测试；旧分支不变是源码/单测证据，不冒充真机复验。

## 各设备共有的网页按钮几何

已核对固定官方 bundle：同一播放/暂停按钮始终使用 `btn_pc_minibar_play` ID，但仅播放中带有 `.play-pause-btn` 类。批准布局的一般按钮规则为 `28×32`，较高优先级的 `40×40` 规则只匹配该状态类。因此暂停时丢失状态类，就被压成椭圆；这不是 Android 16 专属问题。

生成器增加单独、清理可撤销的 Android 纠错样式，以固定 ID 为两种状态设置 `40×40` 及相同 min/max/flex 约束。只作用于 `rb-music-mobile` 适配中的原底栏，不改原按钮、React 父子归属、SVG、事件或官方播放逻辑；原桌面布局不受影响。

批准参考和其中 CSS 原文仍逐字不变；新规则位于宿主自己拥有的独立 style 节点，撤销适配时一起移除，不能误称所有生成 CSS 都未增加规则。

当前手机暂停态截图的红色按钮外轮廓由约 `91×104` 物理像素变为 `130×130`，圆形已确认。没有触发真实播放；播放态依据官方共同 ID、同一尺寸规则与生成回归覆盖，**不是实际播放中截图验收**。机主报告其他设备也有此问题，修正规则没有按 SDK 限定，但本轮没有重跑所有设备/窗口矩阵。
