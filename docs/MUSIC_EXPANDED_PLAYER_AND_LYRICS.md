# 完整播放页与歌词：v1.0.4 累计开发记录

本轮由机主在启动／控件预览后另行授权，并纳入[v1.0.4](releases/v1.0.4.md)。下文保留各私有候选的观察范围，不追改v1.0.3历史资产，也不恢复延期的全面设备矩阵。

## 完整播放页：当前手机竖屏已观察，其他模式／窗口待验

此前适配主要覆盖主页面和 `DefaultBar`，没有覆盖展开后的完整播放／歌词页。官方 `VinylPageLayout` 按桌面左右栏向节点写入宽高，窄窗口仍保留两侧留白与中间间距，导致标题／署名／标签被挤成竖列；展开底栏也不是原来的迷你底栏。

新源码 `tools/music/netease_expanded_portrait.css` 由 `tools/music/build_android_layout.py` 注入单独拥有的 `rb-music-expanded-style`：

- 把官方布局改为同一列的标题信息、唱片、歌词区；`display:contents` 展平布局盒子，不移动／复制 React 节点，不接管其事件。
- 覆盖该组件写入的桌面宽高，保留真正的歌词滚动区与原滑条；标题署名单行省略，不把歌词当 HTML 渲染。
- 展开底栏单独排列中央播放控制和下方辅助／时间按钮；播放／暂停共同 ID 都约束为 44×44。
- 短窗口（包括需适配的手机横向窗口）暂不显示唱片，优先保留元信息、歌词和控制区；没有缩放整个页面。
- 单独调整官方纯歌词模式的边距。其他特效／封面模式、评论切换和所有小窗组合仍需进一步检查，不能称为均已适配通过。
- 不覆盖官方展开／收起／评论 transform，不新建播放器；切回“平板 AND 完整窗口 AND 横屏”时随宿主适配一起撤销，批准参考与其 CSS 原文逐字不变。

这批也重新绘制 API 36 心形：缩小横向视觉占比、用连续曲线形成更圆润的肩部与下尖；空心／实心轮廓和外接范围一致，仍根据真实喜欢状态选择，API 35 及以下路径不变。**当前手机系统媒体卡片已观察到新空心轮廓，审美仍由机主确认；未点击真实喜欢操作构造实心态基线。**

## player2 跟进：顶部空间与自动滚动可见性

机主随后使用有歌词歌曲指出：player1 的收起按钮右侧仍大片留空，标题另占一行；歌词在正常自动滚动时看不到当前句。机主稍微手动调整后的截图仍有高亮行被歌词区上沿裁切，**该截图不能冒充正常自动滚动基线**。此前纯音乐／暂停资源的有限观察没有覆盖这个问题。

已核对固定官方 `LyricDisplayInner` 的经典模式：`withOffset` 把滚动目标设为“整个窗口的中线减去歌词区顶部”，不是歌词区自身的中线。player1 把较大的唱片纵向堆叠在前面，使歌词区起点落在窗口中线以下，目标偏移成为负数。不能只扩大高度、去掉遮罩或另写一个滚动器掩盖它。

`1.0.4-dev-player2` 只修改独立拥有的补充 CSS 和生成资产：

- 标题使用原收起按钮右侧空间，署名利用下方全宽两列，来源独占下一行；不移动 React 节点。
- 去掉此前顶部 56px 预留，改为 8px；元信息行按内容确定高度，唱片行缩为窗口高度的 20%（上限 200px）。
- 760px 及以下短窗口不显示唱片，优先保留歌词；这是布局规则，**不是所有小窗已验收**。
- 让歌词区起点处于官方窗口中线之上，继续使用原来的高亮、滚动与选择逻辑；不改官方 ref／props／事件，不设置歌词 scrollTop 或另造自动滚动。

已覆盖安装当前 Redmi，安装字节、UID 与安装前最新默认浏览器核对一致。安装时原状态为暂停 54880ms；随后由机主主动正常播放，助手仅作只读截图，观察到约 81610ms 时多行原文及翻译的当前高亮完整可见。机主反馈“我看着倒是没有问题了”。这是**当前手机竖屏／当前歌曲的正常自动滚动与顶部布局确认**，不是全部歌曲／模式／旋转／seek／试听矩阵，也没有自动播放、暂停、跳进度、改喜欢／音量或熄屏设置。

原完整页第一批／心形及歌词取数的历史证据保留如下；当前安装预览为 player2，仍没有正式发布。

## 歌词取数：第一批只读基础与后续原生接入

第一批固定 provider 新增 `lyrics(expectedTrack)` 时，原生入口／浮窗尚未接通。后续 `lyrics1/lyrics2` 已接入原生有界模型、同一系统媒体按钮的三态桌面浮层及显式权限入口，见[桌面歌词的实现／证据／未完成项](MUSIC_DESKTOP_LYRICS.md)。系统／车机歌词发布仍没有接通；下方 player1/player2 的观察保留历史范围，不冒充新功能全验收。

- 使用当前音乐 WebView／Profile 中固定官方模块 15 的 `Rf`；只对当前歌曲发 `/api/song/lyric/v1` 的固定参数调用，不允许传任意 URL／模块／动作，不借用网易云原生 App 的认证或歌词。
- 固定官方模块 519 的解析器处理逐句／逐字降级、时间戳及官方 offset。官方格式化器先把 offset 从毫秒转秒，解析器已扣除一次；门面仅将最终秒数换成毫秒，不能重复扣 offset。
- 只有已认证、播放文档且原 SDK 状态订阅就绪才能读取；需匹配当前歌曲和 playId。云盘／非数字资源暂返回不可用，不自行绕过权益。
- 最多一个实际未完成请求；8 秒过期**不释放**其槽位，不允许超时后叠加请求。切歌／换 playId／文档销毁后旧返回丢弃；同曲成功或失败结果缓存到身份变化／文档结束。
- 进入官方解析器前文本总长上限 262,144 字符，最多 512 行、每行 256 字符；只返回状态、当前歌曲标识和有界 `{time,text}`，不输出账号／Cookie／音频地址，不持久化歌词。
- 区分无歌词、无同步时间、过大、失败及超时；不伪造歌词，不用歌名填充来假装同步成功。读取没有播放／喜欢／音量动作。

## 当前证据

- 当前 9 项生成／样式源码回归，含批准 CSS 字节一致、样式独立归属／作用域、展开布局及短窗规则、心形两态轮廓；新增经典模式中线定位的有界算术夹具，旧堆叠布局得到负目标，新规则在夹具内为正且保留多行空间。**算术夹具不是实际 CSS 引擎／所有窗口几何验收**。
- 布局 host 7、内存 9 场景继续通过；1,000 次适配切换后新样式节点也被清理。
- 歌词 18 个 fake API／parser 场景：门禁、单待执行请求、曲目／playId 关联、超时不洪泛、迟到／销毁响应、范围及文本边界，不改变播放。**不是实际登录 Profile 取数验收。**
- 一次无登录公共官方 GET 返回 code 200，同时存在逐句／逐字／翻译／罗马音格式；保留的官方解析器得到 49 个有时间戳的行。这证明该次公共响应／解析合同，不证明当前账号、当前歌曲、试听、所有网络或车机兼容。
- 全量 JVM 243 项通过；全量 Debug Lint 0 error／49 warning。
- 私有 `1.0.4-dev-player1` 已按完整 R8／资源裁剪、压缩 DEX、无损 ZIP、对齐后原证书签名完成打包验证，并已在机主手动解锁后覆盖安装 Redmi。安装包与候选逐字节一致，UID 与安装前最新默认浏览器保留，原登录继续有效；未增加悬浮窗权限、调试或测试入口。
- 当前手机竖屏展开页已观察到完整单栏元信息、居中唱片、下方歌词／原滑条、未换行的底部时间／控制；系统媒体卡片观察到细化的空心心形。保持原暂停状态及 123000ms 进度，未操作真实播放／喜欢，未改音量／静音／勿扰／熄屏设置。未把这一个经典展开页扩展为纯歌词模式、全部窗口／设备通过。
- 临时、同签名、只读测试辅助程序在本应用实际音乐 WebView／Profile 中调用固定歌词读取，得到 `ready`、身份匹配、4 个定时条目，正文长度均在界内，暂停及进度保持。启动到读取完成 1514ms，**不是单独歌词接口耗时**。只输出行数、时间和布尔值，不导出账号、歌曲 ID、标题或歌词正文；完成后辅助包已禁用，重新正常打开生产音乐页。当前资源的四个条目不能代替有歌词歌曲逐句跟随、seek、试听或切歌故障验收。

## 接续事项与诚实边界

1. 当前经典展开页与图标已有上述限定观察，player2 的顶部／正常滚动可见性另获机主当前场景确认；纯歌词页、其他窗口仍待验。后续交互前重新确认亮屏／解锁，不自动唤醒／解锁，不改变音量或熄屏设置。
2. 本应用自己的音乐 Profile 只读取数已得到一次真实结果；原生模型／右侧三态动作已接入，但有歌词歌曲的真实浮层逐句、暂停／seek／试听坐标与切歌关联仍待验。
3. 桌面歌词按[后续要求](MUSIC_DESKTOP_LYRICS.md)实现，锁定透明／无说明文字及当前手机三态／位置记忆已有有限观察。特殊权限仍必须由机主明确允许，不做 ADB 静默授权；任务清理／更多窗口与实际穿透仍需补验。
4. 系统／OEM／蓝牙输出与桌面浮层分开。Android 公共 MediaMetadata 没有通用歌词键，标准 AVRCP 常规曲目信息不等于逐句歌词协议；需要核对具体接收端。不能仅写自定义 extras 就声称系统／车机已支持，更不能悄悄把歌名替换成歌词。
5. 另一个 WebPlayer 问题仍待机主描述，不猜测扩大修改。
