# 音乐启动优化：v1.0.4 累计开发记录

本页保存 **v1.0.3之后、纳入[v1.0.4](releases/v1.0.4.md)的开发过程**，私有候选数字不自动等于最终APK专项复验，旧标签和资产不变。本轮机主另行授权针对手机启动、适配和卡住情况排查；不恢复此前取消或延期的完整设备矩阵。

## 时间口径

机主日常录屏按 0.1 秒抽帧：启动动画约在片内 3.5 秒开始，检查登录约 3.7–5.2 秒，准备播放器约 5.2–8.2 秒，业务界面约 8.3–8.4 秒出现。界面前等待约 **4.8–5 秒**，不包含出现后推荐和封面等内容的加载。

早期目标进程重启探针曾记录约 26 秒；它不是同一启动条件，不能当作日常基线。后续对照使用正常导出音乐入口和自目标测试辅助程序，不通过重新启动整个主应用来计时。

系统媒体会话就绪与网页第一帧是不同指标。私有预览的有限亮屏/解锁观察得到会话就绪约 0.9–2.35 秒、状态保持暂停；这不是固定启动保证、声学监测或所有网络下的首帧结果。

## 轻量官方登录校验

- 固定地址 `https://music.163.com/api/w/nuser/account/get`，对应已核对官方模块 15 的 `Ah` 调用；不是猜测的第三方接口。
- 仍使用服务持有的**同一个音乐 WebView、同一个专属 Profile**，默认正常手机 UA，直接加载真正的 HTTPS 响应文档。
- 每次检查带新 nonce，校验期间使用该 WebView 的 `LOAD_NO_CACHE`，转入登录/播放器或回退时恢复默认缓存策略。不伪造网页来源，不把 Cookie/token 复制到原生 HTTP 客户端。
- 固定脚本仅在正确官方主文档完成后解析有界 JSON，返回 `yes/no/unknown`。只有成功响应中的正数 profile user ID 认证成功；账号资料和 ID 本身不返回原生层。
- 明确失效进入原版手机登录页；错误、异常结构、重定向或 3 秒超时仅触发**本轮一次**原官方 WebPlayer 校验回退，不误判为退出登录。nonce、文档代次和错误锁存拒绝旧回调。
- 官方登录成功回跳 HOME 后自动进入上述校验；不定时跳离手机号/验证码输入页。进入电脑 UA 真 WebPlayer 后仍执行官方账号校验。

已在原音乐 Profile 内观察一次真实正登录响应，约 305 毫秒。未登录公开响应及三态/异常由独立检查覆盖；没有清除真实 Profile 来制造失效基线，完整失效/扫码/权益矩阵仍未验收。

## 消除人为等待与避免无限等待

账号确认后立即建立四种官方订阅，不必等下一轮固定轮询；收到冷启动暂停提交回执后立即读取新状态，确认暂停且非缓冲后才放行。页面完成也可提前唤醒下一次固定读取，正常轮询仍作兜底。

超时从不假装取消真实未完成的 `evaluateJavascript`，也不提前释放其槽位。初始化有 30 秒预算；真实登录输入和已就绪运行时不受该预算打断。未完成时显示重载提示，不无限追加检查，明确重试执行新的导航并保留 Profile。

原 provider 的连接预算曾在模块登记开始后才计时；若 bundle 或 Webpack 引导缺失，可能永远不开始计时。开发树将这一阶段纳入预算，增加缺失引导的离线负对照。这不等于已证明所有实机卡住都由它导致。

## 已复现的停止/重开交接故障

在确认亮屏、未锁屏的连续重开中，观察到音乐任务仍存在，但服务已停止、运行时已释放。界面保留默认“检查登录”文字，实际上此实例已没有运行中的登录校验，不能归咎于网络等待。

修复包含：

1. Activity 连接时先拒绝已关闭服务，再进行有上限的解绑、停止与重新绑定；有限失败给出明确重试入口。
2. 旧 Activity 仅释放自己拥有的任务，不能通过全局停止组件误关替代任务的服务。
3. 旧任务移除回调不能停止仍存在的当前替代任务；现有任务监测继续兜底。
4. 原生服务通过 Android 的 DUMP 保护路径仅报告固定生命周期布尔值和阶段，不输出任务 ID、账号、媒体、URL 或任何任意执行能力。

加入旧任务释放、无关任务移除、已关闭 Binder 拒绝的 JVM 回归；修复预览连续重开四次均观察到存活的任务/运行时及暂停会话。不是完整进程恢复、所有旧通知或所有 OEM 的证明。

## 布局与证据边界

保留批准参考及 CSS，只修正原生左右安全区/挖孔和键盘 inset 的取最大值处理。未启用未经验证的可见 WebView/原生遮罩替代方案，也没有可见性伪装、页面缩放或系统旋转写入。

短录屏还发现 SDK 就绪早于布局安装时会短暂露出未适配界面。开发树增加固定布局 `ready/prepare` 门面；冷暂停时可及时安装，非原桌面窗口需布局就绪后再初次显示。轮询受原有单槽和初始化预算限制，不靠提前展示错误界面缩短数字。首次安装还会触发批准 CSS 原有的约 240 毫秒侧栏收起过渡；生成器只在安装期间临时禁用该节点的 transition，强制结算关闭布局后恢复原值和优先级，日常抽屉动画不变。最终亮屏/解锁录屏按 8 fps 检查，首次业务界面出现时侧栏已关闭，本次从原生启动动画到界面约 1.6 秒；推荐内容随后继续加载。会话就绪为该次约 1.77 秒，二者不是同一计时指标，也不是固定时延保证。期间一次熄屏导致录屏 `INVALID_LAYER_STACK`，该次没有算作前台画面通过。

本轮自动检查：全量 240 JVM；两种极简各 16 项共享音乐策略/生命周期定向测试（不是各 183 项全套重跑）；账号 reader 41、布局 host 7、内存 9 场景及生成一致性 3，另有 provider fake SDK/DOM/audio 检查。旧正式 provider 在新增订阅衔接和缺失引导负对照中失败。

## 后续界面修复，不包含在本轮启动通过项

机主指出并已截屏确认：系统媒体卡片左侧是星形而非期望的“喜欢”心形；应用内暂停状态下的红色播放按钮被压窄成椭圆，与播放中的暂停按钮形状不一致。按机主顺序先完成上述启动任务，随后在[独立控件修复记录](MUSIC_CONTROL_UI_FIXES.md)处理中；当前预览已修正本机空心心形及暂停态圆形，实际播放/真实账号喜欢切换仍未专项验收。不能把系统会话/暂停状态检查当成完整 Android 16 媒体卡片或全部手机布局验收。

不修改系统音量/静音/勿扰、自动熄屏、锁屏、WebView 提供方或网络设置；不使用 root、不清数据、不卸载。真实认证和系统确认由机主处理。临时辅助包测试后禁用；截图、录屏、原始设备输出和账号环境只留私有证据目录，不进入仓库。正式发布需另行确认，不移动旧标签或替换旧资产。
