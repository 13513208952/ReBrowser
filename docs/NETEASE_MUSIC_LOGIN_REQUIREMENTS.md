# 音乐登录前置与 UA：机主确认的硬性要求

**交接／压缩后必须先读本文件。** 这不是可选优化；历史首轮预览曾遗漏该流程，现已由正确登录流程替换，不能恢复“启动即固定电脑 UA 直入业务”的旧方案。

当前状态：正确登录流程已集成正式 **v1.0.3**，机主平板已观察到原版手机页登录后自动进入同 Profile 电脑 UA WebPlayer，无需手动检查；最终全量包已覆盖更新手机，但没有追加登录专项。完整登录失效/取消/扫码及窗口矩阵移至后期大版本，本轮手机/Android 16 专项由机主取消；不把有限观察扩大为全面验收。[当前验收范围](NETEASE_MUSIC_RELEASE_ACCEPTANCE.md)。

## 1. 登录是进入音乐界面的前置条件

检测到未完成登录时，必须先进入网易云**原本正常的手机 UA 登录界面**，让用户完成官方登录；不能先展示音乐业务界面并把登录当作可选项。

未登录或登录状态尚未确认，均不得放行到音乐界面。不能仅凭 Cookie 存在、页面加载成功、曾登录过或出现某个账号 DOM 就认定已经登录；应验证官方有效登录状态，不导出账号、Cookie 或 token。

不能自建账号／密码／短信／验证码表单，不能拿电脑 UA 扫码页替代普通手机登录页，也不能把桌面登录页缩窄后称为手机登录界面。确切官方手机登录入口、正常跳转和状态检查需核对此前验证资料及当前网页，不凭猜测拼接路径或私有调用。

## 2. 登录阶段 UA 决策表

默认始终是**正常手机 UA**。电脑 UA 扫码登录的可切换入口只有一个例外：

| 登录所需时的设备／窗口状态 | 默认 UA | 允许用户切换电脑 UA 扫码 |
| --- | --- | --- |
| 手机，任何方向／窗口 | 正常手机 UA | 不允许 |
| 平板，完整窗口且横屏 | 正常手机 UA | **允许，必须由用户主动切换** |
| 平板，完整窗口但非横屏 | 正常手机 UA | 不允许 |
| 平板，分屏／小窗／PiP，即使窗口横向 | 正常手机 UA | 不允许 |

**平板完整窗口横屏也不能自动默认电脑 UA。** 不满足“平板 AND 完整窗口 AND 横屏”且仍需要登录时，必须使用正常手机 UA 登录。

若登录过程中设备／窗口状态改变，已不满足例外条件，登录 UI 必须回到正常手机 UA，不应继续保留仅在例外状态可用的电脑扫码模式。

设备类型、窗口状态、方向和 UA 是四个独立判断项：沿用原生设备分类／手动覆盖、Android 多窗口与 PiP 标志、窗口 Configuration；不要以 UA、网页尺寸、输入法缩小后的 WebView 高宽或当前／最大窗口尺寸差推断平板及完整窗口。OEM 标志遗漏需如实处理，不私自引入尺寸猜测或系统旋转写入。

## 3. 登录成功后

**登录检查必须自动进行，不能要求用户点击“检查登录”才继续。** 机主补充确认的官方手机入口是 `https://y.music.163.com/m/login`。源码使用该页面支持的 `redirect_url` 固定回跳 WebPlayer；原版登录成功回调自动跳转后，再由 WebPlayer 的官方账号读取接口确认。手动操作仅作异常重试，不是正常登录步骤，不定时跳离正在输入手机号／验证码的页面。

确认官方登录成功后，使用**同一音乐专属 Profile**切回电脑 UA，加载真正的官方 WebPlayer，再按已确认的非横屏布局适配。电脑 UA 在此是业务页面显示策略，不意味着进入原生 PC 客户端分支，也不替换 WebView 引擎。

UA／页面切换不复制、导出或搬运 Cookie/token。音乐专属 Profile 与原浏览器已登录 Profile 的边界保持不变；原浏览器数据和登录环境必须保留。

登录失效后重新进入上述登录前置流程，不能继续当作已登录音乐界面运行。CAPTCHA、扫码确认、短信及网站权益限制必须保留。

## 4. 后续另行获准验收时优先检查

1. 机主原话与后续补充是约束依据；当前全面开发已获准，不自动恢复另行停止的第三方调查。
2. 核对 `ReBrowserMusicLifecycle`、`ReBrowserMusicRuntime` 与固定 provider 的门控：任何未知或过期状态都不能回到旧预览的固定电脑 UA 直入业务流程。
3. 在同一音乐 Profile 验证：首次登录、已有有效登录、登录失效、取消／失败、扫码切换，以及旋转、分屏／小窗／PiP 变化。
4. 测试断言：未登录无法进入音乐界面；例外条件三项全部满足才提供电脑扫码切换；例外状态默认仍为手机 UA；非例外状态不得停留在电脑 UA 登录。
