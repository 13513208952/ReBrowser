## 平板短测记录（2026-10-15）

设备为 API 33 平板，WebView 155.0.8059.4。RC2 全量 Release APK SHA256：`46f9723781c6b6a7c270b20267f8a2fdbc284e8b2ce4ba8102b7ada4e9bd98b4`。原证书、v2/v3、对齐、压缩 DEX、打包前后解码字节/条目顺序/注释/STORED 保留及无调试/明文配置已检查。测试辅助 APK 使用自目标 instrumentation，确认启动辅助测试没有重启正式应用进程。

- RC1：系统喜欢/取消喜欢均观察到状态更新，结束恢复原喜欢状态；暂停 seek 到 10,000ms、播放 seek 约 20,908ms、暂停位置稳定和继续推进、下一曲及上一曲返回原曲目均有设备记录。仍需必要的最终候选复验，不能据此覆盖 Android 16 或试听边界。
- 机主切换流量热点后，不追加代码/换 APK，RC2 连续两轮真正新建音乐运行时：自动登录验证与播放器就绪均约 6.3 秒；先保持暂停采样，再由系统媒体控制首次播放，均在原曲目上推进，观察窗口分别约 6.3/4.7 秒。启动后没有触碰 WebView DOM 来预先取得网页手势。
- 第二轮从实际播放状态划掉音乐任务，服务/会话退出；重新进入仍是原曲目且暂停，恢复位置与移除前最后采样差 -419ms。完整队列/页面恢复、实际输出与所有瞬时行为仍不能由这些采样概括。
- RC2 保留旧 MediaController，划掉音乐任务并新建运行时；待新会话稳定暂停后，向旧控制器发送 play/next/seek，新会话仍暂停、曲目/位置未变。仅证明旧控制器链路，不替代旧通知 PendingIntent/nonce 或进程重建验收。
- 此前初始化超时、首次系统播放未推进/转曲的异常，按机主要求记作旧网络条件下的异常；热点复测通过后，不再作为当前候选已确认的软件缺陷追改。RC1→RC2 本身也含此前的原生播放授权调整，因此这些记录不是“全部旧异常仅由网络造成”的严格单变量证明。
- 机主明确接受搜索建议的原站交互：点击其他位置收起，不要求第二次 Native Back 关闭，也不以此阻塞发布。热点下实测真实点击外部后搜索建议标签由 2 变为 0；这不是其他队列/歌词/模态框/路由/退出的返回验收结论。

### 限定平板验证完成

- 同一 RC2 复验：暂停/播放 seek、暂停位置稳定、播放推进、喜欢/取消喜欢及重复同一期望状态均通过，恢复原喜欢状态；下一曲与上一曲返回原曲目。重复期望为串行控制，未外推并发/极慢网络幂等。
- 临近曲尾的合法 seek 后回到 Home，观察到自动切换不同曲目标识并继续推进约 3.2 秒；不是同曲回绕。
- 实际约 541.6 秒，前台、Home 后台、息屏各 180 秒，每 30 秒取样，共 18 点。18 点均为 PLAYING，app 和所属 renderer 两个 PID 稳定，WebView 数恒为 1；没有修改机主原有屏幕超时或添加常亮。

- 播放时 18 点观察到音乐 PARTIAL_WAKE_LOCK；终止仅属于音乐的单任务 root 后，连续 5 次采样均无音乐服务、媒体会话或活动音乐唤醒锁，应用进程也已退出。此前真实最近任务划除已单独验证；最后一次使用系统公开的、限定目标的 task removal，不冒充 UI 划动。
- 原默认浏览器角色未变；未卸载/清数据/删除 Profile，未修改 swap/OOM/网络权限或解锁绕过。辅助测试包已停用。息屏测试结束只唤醒屏幕，锁屏交由机主处理。
