# 项目状态

本页汇总历史开发阶段报告的实现、验证、当前限制与候选方向。它不是兼容性承诺；其中既有真机验证，也有自动化或模拟测试，具体范围见[开发历史与验证资料](DEVELOPMENT_HISTORY.md)。历史结果不等于本轮已对所有能力重新验证；本轮测试范围见对应版本记录。

- WebView Cookie 与站点会话延续；
- `FindConversation`、`GetConversationItems` 和 `GetItem` 结构化采集；

### ReBrowser

- WebView `MULTI_PROFILE` 支持探测；

- 总标签页和子标签页双层模型；
- 临时、副、主生命周期以及副总标签页收起和恢复；
- 多个主总标签页并存、进程重启恢复和延迟 Profile 清理；
- 收藏夹与完整环境书签栏分离；收藏夹已改为单行网址列表并支持行级编辑和删除；
- `target=_blank` 和 `window.open` 在当前总标签页中创建子标签页；
- 桌面双入口、应用内模式切换和统一系统返回策略；
- ReBrowser 管理协议 v2：双永久根、三级授权、结构化结果、对象 ID 控制、加载等待、生命周期、诊断、审计及有界修复；
- WebView 原生全屏视频以及 Bilibili 电脑版视频播放；
- 全局方向切换、横屏全屏播放及退出全屏后的界面恢复；
- 已实现 ReBrowser 下载管理：命名 Profile Cookie、五分钟频率控制、有界待确认队列、进度、取消、重试、删除、SHA-256、风险分类、Data 与固定分块 Blob 提取；
- 已实现下载管理员语义命令、管理员全局启停新下载（禁用时拒绝待确认请求但不破坏运行中任务）及非 HTTP(S) 外部 Intent 收紧；
- 真机验证了 Bing HTTPS 文件下载、命名 Profile Cookie 绑定标记、Data 下载、固定分块 Blob 下载、SHA-256、高频第三次拦截、待确认列表、危险文件二次警告、只读 `content://` 系统选择器交接，以及管理员查询／拒绝／修复／全局清理和全局启停。禁用策略下的新请求无模态框并以结构化原因拒绝，重新启用后恢复普通确认；64 MiB Blob 在 25 MiB 后取消并成功重试至完成，SHA-256 已生成；96 MiB Blob 在进程中断后明确变为 `custom-download-interrupted`，其受控 `.part` 文件在下次启动时删除。
- 已实现按命名 Profile＋HTTPS 顶层 origin 隔离的网站权限管理：剪贴板和模糊定位默认允许申请，摄像头、麦克风和高精度定位默认关闭；敏感能力使用单次／3 小时授权，剪贴板和模糊定位使用 5 分钟／15 天授权；全局关闭会清除授权并重建页面。
- WebView 原生定位已关闭；模糊／精确定位通过固定语义桥区分。网站通知、后台推送和网页运动传感器永久禁用，ReOutlook 显式拒绝媒体与定位请求。
- 已实现后台冻结策略：普通后台页面暂停并静音，媒体页面销毁；关闭后台运行后网页运行时销毁，系统 HTTP 下载继续，依赖页面的 Blob 任务明确失败。
- 真机验证了剪贴板 5 分钟／15 天授权、模糊定位量化、摄像头／麦克风单次与 3 小时授权、origin／Profile 隔离、后台媒体硬件释放和管理员关闭即撤销。关闭后台运行时，约 21 MiB Data 下载在页面销毁后完成并生成 SHA-256，64 MiB Blob 在约 6.9 MiB 后以 `background-runtime-disabled` 明确失败，HTTP DownloadManager 任务在后台继续增长；该 HTTP 测试的远端任务随后以非策略错误 `reason 590` 终止。
- 管理员协议可以查询、单向禁用、清除、校验和修复网站授权，但不能开启能力或创建授权；真机结果只返回 Profile、HTTPS origin、权限类型及期限。校验和修复会识别过期、损坏、未来时间、已禁用、重复和超限记录。
- 已增加 21 个 JVM 回归测试和隔离设备状态的 instrumentation，覆盖 Workspace 生命周期、网站权限默认值、授权撤销及损坏授权修复、频率窗口、待确认上限、管理员授权边界、审计脱敏、下载持久化脱敏、取消竞态、进程中断临时文件清理，以及 POST／未知请求上下文的明确拒绝。
- 最低支持版本现为 Android 10／API 29；Android 8/9 留待未来采用完整浏览器内核路线时重新评估。

上述历史验证主要使用 Google Android WebView 149.0.7827.48。运行时仍然保留功能检查；不支持 `MULTI_PROFILE`、`WEB_MESSAGE_LISTENER` 或 `DOCUMENT_START_SCRIPT` 的提供者不会启用 ReBrowser。

链接新开的子标签页现在记录运行时来源：全局返回先退当前页内历史，到入口后关闭子标签页并返回来源页；连续打开可逐级返回，不以标签排列顺序推断来源。手动新建或切换不创建来源关系；来源关闭、工作区切换、收起和重启后不沿用失效路径。具体行为见 [ReBrowser 设计](REBROWSER_EXPLORATION.md)。

## ReOutlook 桌面入口显隐（v0.4.3-alpha）

ReBrowser 设置新增“显示 ReOutlook 桌面入口”开关，默认显示，选择由 Android PackageManager 保存。仅控制独立桌面 alias，不禁用 MainActivity；浏览器菜单切换到邮件仍可用，不改动邮件数据、Profile 或网站权限。首次升级会将原 MainActivity 的 launcher filter 迁移到 alias，桌面图标刷新时机和排列由启动器决定。

管理员协议 v2 新增一级只读 `GET_LAUNCHER_STATUS`（CLI：`launcher-status`），并在 capabilities／diagnostics 中增加固定状态快照；沿用原挑战、授权、结果与审计，不增加管理员 setter 或任意组件操作。查询可以直接在受保护管理员 Activity 完成，不加载网页。

本轮新增 7 个 JVM 测试，总计 53 个通过、0 失败；39 项 Node.js 策略检查通过；Release 构建和 Lint 通过（0 错误、26 警告）。真机同签名升级安装了非调试预览，验证默认显示、隐藏后启动器只保留 ReBrowser、菜单仍能进入 MainActivity、隐藏状态跨重新安装／进程重启保留以及恢复显示。验证结束恢复原来的显示状态。此功能与历史记录一起在 v0.4.3-alpha 发布，其他启动器的缓存表现未逐一验证。

## 历史记录（v0.4.3-alpha）

[历史记录说明](REBROWSER_HISTORY_PLAN.md)记录了确认规则与实现细节。菜单入口位于书签栏下方，列表最新在前，支持逐条删除和分页。私有 SQLite 将副／主总标签页历史长期保留；临时来源每次访问保留 30 分钟，副环境收起后相关历史再保留 30 分钟。子标签页关闭不改变历史期限。

维持按钮以灰色三角形／红色方块区分状态，跨重启保存，开启时禁用带“30”的清理按钮；结束时有限期限记录重新获得 30 分钟。面具只暂停访问列表写入，进程重启默认关闭，切后台不会重置；结束暂停后，为所有仍打开的总／子标签页补记当前网址和标题，不重新加载、不补录中间过程。到期由时间戳在读取／记录等时清理，没有后台倒计时服务。

历史新增 27 个 JVM 检查；与入口显隐合计，本版总计 80 个 JVM 测试、39 项脚本检查通过；干净 Release 构建成功，Lint 0 错误、26 警告。真机验证了实际记录、暂停期间不新增、恢复时对三个打开页面同步、关闭子页后长期记录不变、收起来源转换期限、维持期间禁用清理／允许单条删除，以及重新安装后的维持与暂停状态区别。精确期限与全量临时清理由模拟时钟和界面测试覆盖，未把真机观察当作全部组合的完整验收。

最终 versionCode 14 非调试 Release 包已原地安装，191,294 字节，R8 优化、裁剪、混淆、资源裁剪及 DEX 压缩继续开启，无内网 HTTP 例外。管理员新增一级只读 `history-status` 和历史界面路由，结果不返回历史网址／标题明细，不开放任意数据库操作。安装后历史界面三个按钮及查询正常，无存储错误。

## 后续界面与防护设想（待讨论）

详细设想见[新标签页与个性化讨论记录](REBROWSER_NEW_TAB_PLAN.md)，其中新建空白总标签页按机主方向以 `about:blank` 判断，新建未分配网址的子标签页仍默认打开首页。历史记录已实现，期限与控制规则见[历史记录说明](REBROWSER_HISTORY_PLAN.md)：保留期跟随整个总标签页，子标签页关闭不影响历史；副总标签页收起视为关闭；维持状态跨重启保留，暂停状态不跨重启保留；结束暂停时同步所有仍打开页面的当前网址与标题，不重新加载。ReOutlook 桌面入口显隐和历史记录未并入 v0.4.2-alpha，随后一起在 v0.4.3-alpha 发布，情况见上节。
- 界面个性化与独立于首页的新标签页需要一起讨论设计；现代挖孔屏的安全区域、横屏和全屏适配也是后续方向，目前不扩大实现范围。
- 将“是否允许明文 HTTP”纳入未来防护自定义界面的讨论。默认值、作用范围以及与防护模式的关系尚待确定，不在此轮直接开放。
- 当前正式网络策略仍禁止明文 HTTP。内网进度测试曾使用仓库外的临时资源覆盖，仅放行测试电脑 IP；最终 Release 已检查没有该例外，测试服务器已停止。

以上记录讨论方向与本次预览反馈，不代表完整设计、实施顺序或永久要求。

## 当前限制

- 项目没有接受独立安全审计；
- 第二个真实 Outlook 账号隔离尚未端到端验证；
- 超过 20 封邮件的真实长会话仍缺少样本验证；
- 远端删除、移动和复杂同步失败恢复仍需继续测试；
- ReBrowser 仍基于系统 WebView，不具备完整浏览器内核产品的全部能力；剪贴板和传感器禁止依赖文档启动策略，而不是 Chromium 内核 Content Setting；
- ReBrowser 管理接口仍是有界语义命令集，不提供任意脚本、数据库或私有文件访问；
- 新增的三段视频方向覆写已完成构建和设置界面检查，所有策略组合尚未逐项手工验证；
- WebView `DownloadListener` 不提供原始 POST 正文或完整 Service Worker 请求上下文；ReBrowser 只接受 WebViewClient 同页观察到的 GET 下载，已观察到的非 GET 请求以 `unsupported-request-method` 拒绝，无法关联请求上下文的回调以 `unsupported-request-context` 拒绝，仍不能承诺 Chrome 级兼容性；
- 仍需用必须登录且服务器实际校验 Cookie 的下载端点验证端到端登录态；
- 面向普通用户的显式备份与恢复尚未完成；
- 当前公开 APK 使用开发者 Debug 证书签名，不是长期生产发布密钥。

## 历史候选方向（待讨论）

以下保留此前文档提出的方向，不表示已批准实施，编号也不代表当前优先级。项目以实际目的驱动，现有方案和这些候选项均可根据项目所有者的新建议调整、替换或取消。跨子标签页返回和 YouTube 播放修正已完成并发布；无痕模式仍暂缓，也不因此批准下列其他候选项。

1. 补充验证必须登录且服务器实际拒绝无 Cookie 请求的真实下载端点；
2. 在 GPS 信号良好的环境补测高精度定位真实坐标结果；权限升级、拒绝和超时链路已经验证；
3. 设计无痕工作区与命名 Profile 生命周期，并继续完善站点信息、分享、深色模式和受限历史恢复；
4. 验证 Outlook 长会话、远端删除和第二账号隔离；
5. 将 SQLiteOpenHelper 数据访问层迁移到 Room；
6. 实现带同账号验证、加密和回滚保护的普通用户备份恢复；
7. 评估基于 GeckoView 与 Android Components 的下一代完整浏览器实现。
