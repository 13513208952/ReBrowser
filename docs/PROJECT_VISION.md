# ReBrowser：重新定义浏览器

**Re，不是给既有浏览器增加几个功能，而是重新审视、重新组织浏览器能够成为的东西。**

ReBrowser 是一个以浏览器为基础的实验性项目：探索如何打破应用封闭环境带来的使用边界，并扩展浏览器参与实际应用场景的能力。通用网页浏览、ReOutlook 邮件与ReMusic音乐子应用，是同一方向上的不同实践，不是项目的最终边界。

## 定位原话

机主对本轮文档定位的表述：

> rebrowser,其中re的意思，在于重新定义浏览器，把浏览器回炉重造，让其真正发挥其应有的能力。这个软件与常规的浏览器和使用chromium开发的手机app都不同-我们的项目展现了浏览器真正完整的能力，是一次打破app封闭环境边界，又扩张浏览器应有能力的一个实验性项目，这种定义会更适合现在的项目。

这里的“完整能力”是项目探索浏览器角色的方向，不表示当前已经实现完整Chrome／Chromium产品能力、支持所有Web标准或兼容任意网站。

## 不把浏览器止步于网页入口

常规浏览是必要组成，但项目不以地址栏、标签页或某个网站的专用外壳为终点。我们探索的是：

- **独立的应用环境**：按用途组织登录状态、持久化、任务和生命周期，而不是把所有服务塞进一个共享会话。
- **网站仍负责其业务**：保留服务自己的官方页面、登录、验证码和权益机制，不另外编造认证或替代服务。
- **浏览器参与应用能力**：在具体适配中结合本地数据、离线展示、权限管理和Android系统交互，使Web服务可以按应用的方式被使用。
- **宿主承担明确责任**：管理环境之间的边界、后台运行和原生能力，而不是把无限制的系统权限交给网页。

ChromeOS可以作为理解这一方向的参照：Web不只是“被打开的页面”，也可以成为应用组织方式。但ReBrowser目前是运行在Android上的应用，不是ChromeOS移植版，也不是新的操作系统。

## 当前已经落地的实践

| 形态 | 当前实践 | 不是 |
| --- | --- | --- |
| 通用浏览 | 双层标签、独立命名Profile、环境持久化、原生搜索页、历史与站点权限 | 完整无痕保证或自研浏览器内核 |
| ReOutlook | 官方Outlook会话、结构化同步、本机邮件缓存与离线阅读 | Microsoft官方客户端、独立邮件服务或任意邮箱平台 |
| ReMusic | 官方网易云WebPlayer、独立任务／Profile、布局适配、系统媒体控制与可选桌面歌词 | 音源提取、权益解锁、替代播放器或通用车机歌词发布 |

这些实践证明项目已经超出“只负责打开网页”的定位，但并不意味着任意网站都能自动成为成熟的子应用。当前适配是具体实现，没有已经交付的通用插件商店或任意应用安装平台。

## 扩展能力，不取消边界

“打破封闭环境”指拓展服务的使用方式，不是绕过Android沙箱、网站认证、版权、付费权益或用户授权。

- 使用Android系统WebView，不宣称包含完整桌面Chromium或自研内核。
- 浏览器、邮件、音乐有不同网页环境，但仍属于同一个Android应用沙箱／UID；Profile隔离不等于操作系统级独立应用隔离。
- 原生桥、管理接口与系统集成各有固定范围，不开放任意代码、模块、网络或凭据导出。
- 功能实现、有限设备观察和全面兼容保证分开表述；未完成的能力不作为定位宣传中的既成事实。
