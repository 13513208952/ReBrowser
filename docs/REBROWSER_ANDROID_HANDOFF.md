# Android 浏览器注册与 `.1` 安装包交接（v0.4.5-alpha）

这些功能随 v0.4.5-alpha 发布；同签名非调试预览已验证浏览器及系统设置入口，最终压缩背景包也已原地升级安装并核对设置与状态。体积及校验见 [发布说明](releases/v0.4.5-alpha.md)。

## 浏览器与默认应用

- ReBrowser 默认注册 HTTP／HTTPS 的 `VIEW + DEFAULT + BROWSABLE` 接收入口，不增加启用开关，不自动申请或改变默认浏览器。
- 启动器仍不转发外部 Intent。独立 `ReBrowserLinkActivity` 仅接收有效、最多 8192 字符且不含用户凭据的 HTTP(S) 地址，重新构造私有浏览器 Intent；外来管理员参数、selector、ClipData 和 URI 授权不转发。
- 外部链接使用新的临时总标签页和独立命名 Profile，不借用当前网站或 ReOutlook 的登录状态；首次启动且没有持久化环境时不额外创建空白总标签页。满 64 个环境时拒绝新链接，不改写已有页面。原临时生命周期及历史策略保持不变。
- 注册 HTTP 处理能力不放宽正式包的明文网络禁令；HTTP 网页仍受现有网络策略阻止。WebView 能力不满足时仍不回退至 ReOutlook Default Profile。
- 常规设置最后的“选择默认浏览器”按钮仅在用户点击时打开系统默认应用设置，由用户进入“浏览器”自由选择。无论本应用是否已获浏览器角色，按钮都可用；不使用已持有角色时可能直接结束的角色申请对话框。优先解析该标准 action 的系统推荐处理组件，不固定首选包名；只接受导出且启用的系统应用组件，不交给第三方或合成 ResolverActivity。无法启动时兼容回退至厂商 Settings 的默认应用入口，再回退系统设置。
- 两种应用形态共用 `io.github.reoutlook`，某些系统默认应用列表可能使用包级名称 ReOutlook；链接／文件打开入口使用 ReBrowser 名称和图标。

“隔离与权限”中移除“隔离边界”标题及对应静态说明，不改变 Profile、Cookie、网页能力或授权规则。完整无痕依然没有实现。

## `.1` 文件

- 默认注册本地 `content://`／共享存储 `file://` 的 `.1` 后缀文件打开器，支持 QQ 常见的 `.apk.1`；不增加开关或设置项。
- 接收后核对显示文件名，再以 32 KiB 缓冲原样复制到应用私有中转缓存，原文件不改名、不修改、不删除。只接受 Android 包管理器能解析的 APK，不把任意 `.1` 文件当作可执行内容，也不支持 XAPK／APKS 多包安装。
- 单文件上限 1 GiB；中转目录上限 2 GiB，并保留至少 16 MiB 可用空间。复制不在 UI 线程运行，队列有界；离开接收 Activity 取消尚未交接的操作。
- `ReBrowserApkProvider` 不导出，仅通过随机单文件 URI 和只读授权向选定的系统 APK 安装处理器提供副本；无目录浏览、任意路径、写入或网站桥。
- 仅显式启动匹配 APK 安装 Intent 的系统安装器组件（Android 权限控制器或已知 AOSP／Google／MIUI／OPPO／三星安装器包）；单纯声称处理 APK 的系统应用商店也不接受。未知厂商安装器无法识别时拒绝交接，需真机确认后适配；没有第三方安装器选择或静默安装。声明 `REQUEST_INSTALL_PACKAGES` 供系统核查安装来源，但不自动允许“安装未知应用”。系统自行核验签名、安装兼容性及来源权限，最终安装确认由用户完成。
- 中转 URI 24 小时后拒绝新读取；过期文件在后续交接时清理，也可由 Android 清理缓存。没有常驻定时删除服务，不声称文件必然在第 24 小时被物理删除。
- 拒绝应用自身 provider、应用私有 `file://` 路径及 HTTP／HTTPS 文件来源。不新增广泛存储权限；文件 URI 无法访问时直接报错，优先使用发送方授予读取权限的 content URI。

### Android 文件选择限制

系统 Intent 匹配依据 URI 路径和 MIME，不保证能按 provider 的显示文件名选择应用。因此路径保留 `.1` 的 URI 可以匹配；不带文件名的数字／令牌 URI 即使显示名为 `.apk.1`，也可能不在“打开方式”中列出本应用。不能为此把所有文件 MIME 都无条件登记成本应用的处理对象。需用实际 QQ 样本验证并按明确来源适配。

Android 12／API 31 起使用完整后缀匹配；Android 10／11 使用简单 glob 的 1–6 个点号替代模式，常见 `.apk.1` 和版本号文件名已测试，但复杂路径中更多点号可能无法匹配。

## 管理员与验证

固定设置快照新增只读 `general.defaultBrowser`：注册标记、浏览器角色是否可用／已持有、`administratorCanSet:false`。不返回其他默认浏览器身份，不增加默认应用 setter、文件读写／安装操作或网站权限委派。原 DUMP、签名挑战和授权级别保持不变。

两版各 132 项 JVM、39 项 Node 和 6 项 CLI 检查通过；Lint 0 错误／26 条原有警告，优化 Release 构建通过。新增 JVM 覆盖 Android 10／API 29 与 API 35 的注册匹配、恶意 Intent 参数隔离、默认角色已持有时按钮可点、独立 Profile 初始化、逐字节复制／大小拒绝、只读 URI／过期／路径拒绝及系统安装组件选择。

初次完成源码时 ADB 无设备，随后通过有线连接 `XCQWV4EYEIFMBEUO`，确认只有空白临时页后用 `adb install -r` 安装同签名背景版预览包，没有卸载或清除数据。原有设置、桌面入口和全局网站策略保持一致，状态校验有效。手机验证了包定向 HTTP／HTTPS Intent 注册、常规页最底部按钮可点并打开系统默认应用设置、系统浏览器选择列表含本应用、隔离页说明移除，以及 HTTPS Example Domain 外部链接进入新的独立临时 Profile。测试总标签页与唯一测试历史记录均已清理，默认浏览器全程保持 Chrome。

该手机系统浏览器列表使用包级名称 **ReOutlook**，实际网页接收入口是 ReBrowser。未定向包的通用 Intent 查询因现有默认浏览器策略只列出 Chrome，不据此判断本应用未注册。

机主明确要求 `.1` 留给本人测试，因此本轮没有打开任何 `.1` 文件、触发系统安装器或批准未知来源／安装确认。QQ 实际 URI、未知来源提示、签名核验及最终安装／取消流程仍未验证。本轮从未为了测试而改变默认浏览器。

### 机主推荐的原生默认应用页

机主后来自行把本应用设为默认浏览器，并推荐 Android 权限控制器提供的原生页面，而不是小米 Settings 的旧样式列表。检查发现两个页面都处理 `android.settings.MANAGE_DEFAULT_APPS_SETTINGS`：系统推荐的 `com.android.permissioncontroller/.role.ui.DefaultAppListActivity` 优先级为 2，旧 `com.android.settings/.Settings$AdvancedAppsActivity` 优先级为 1。首版硬编码 Settings 包名，因此绕过原生首选入口。

现已取消首选包锁定，通过限定系统组件的解析与显式启动使用系统推荐入口，并补充固定 action 的包可见性声明。新增 3 项 JVM 检查覆盖首选入口、不接受第三方假冒处理器及 API 29 的旧系统入口兼容。机主中途要求暂停操作手机时立即停止，获准继续后重新读取当时设置和角色，再原地升级背景版预览。

真机在**本应用已持有浏览器角色**的情况下点击按钮，确实打开与机主展示相同的 `DefaultAppListActivity` 页面；原设置、网站策略及机主当前的 ReOutlook 默认浏览器选择保持不变。未点击任何默认应用选择项，`.1` 测试仍交由机主自行完成。

最终 versionCode 16 的背景 APK 用 `adb install -r` 覆盖安装，保留当时最新默认浏览器选择、所有固定设置及全局网站策略，状态校验有效；未卸载或清数据。最终两包的 v2／v3 签名、对齐、压缩内容和网络规则均校验通过。此次没有持久化工作区样本，不宣称真机验证了命名 Profile 迁移；只证明原有偏好和策略保留。最终轻量包没有另外装机，照片排除和资源存储由包检查／JVM 覆盖。
