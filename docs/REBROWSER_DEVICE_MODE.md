# 设备类型与方向策略（v1.0.1-beta）

不改变应用 ID、签名、Profile／数据库格式或三页设置结构。v1.0.0 不包含本页新增功能；本轮以 1.0.1-beta / versionCode 18 发布，正式版保持不变。

## 设备类型

常规页提供自动／手机／平板，手动选择持久保存并优先于自动结果。自动识别采用系统提供的物理 `xdpi / ydpi`，按机主约定将这些数据视为准确；使用最大显示窗口范围，而不是当前分屏宽度。对角线暂以 **7 英寸**为平板分界。

屏幕尺寸或任一物理 DPI 缺失、非正数或非有限数时，自动结果为手机，不用逻辑 dp 推断平板；仍允许手动选平板。Android 11+ 使用最大 WindowMetrics，Android 10 使用完整显示 Metrics。元数据不可读时安全回退，不引入额外权限或库。

## 方向

- 完整窗口指应用不处于系统报告的多窗口或画中画，不是网页视频全屏，也不要求隐藏系统栏。
- 完整窗口且按平板处理：`SCREEN_ORIENTATION_FULL_USER`，允许四个朝向并遵守系统方向锁定；不使用 FULL_SENSOR，不读取陀螺仪，不写系统旋转设置。
- 多窗口／画中画：UNSPECIFIED，让系统窗口管理决定方向。不比较最大／当前窗口边界，也不依赖键盘或内容高度推断窗口状态。
- 手机完整窗口保留既有方向及视频方向行为。
- 平板的浏览器方向锁快捷按钮、手机视频方向控件不生效；旧偏好仍保存，切回手机后可继续使用。
- 原生设置页固定竖屏，退出后恢复浏览器策略。API 36 大屏兼容属性仅放在设置 Activity，不对整个应用关闭适配。

窗口模式、配置、返回浏览器及恢复焦点时重新应用；方向请求相同则不重复设置。厂商不报告小窗状态的情况仍可能漏判，暂不引入猜测规则。系统对大屏／多窗口的方向请求有最终决定权，未宣称全设备强制方向保证。

## 管理员

现有协议 v2 增加一级固定 `SET_PREFERENCE deviceType`，仅 `auto | phone | tablet`；CLI 为 `set-pref deviceType tablet`。该参数可原生执行，无需创建浏览器。其他操作权限、一次性签名、DUMP 与永久根不变。

设置状态提供设备选择、自动／有效类型、来源、物理尺寸及原始屏幕／DPI元数据。浏览器诊断增加实际浏览器 Activity 的多窗口、画中画、完整窗口、请求／配置方向及四方向策略状态；系统自动旋转／用户锁定方向只读。原生回退明确标记浏览器窗口状态不可用，不拿管理员临时窗口冒充浏览器窗口。不提供系统设置写入、传感器读取或任意参数接口。

## 本轮检查范围

35 项针对性 JVM 和 10 项 CLI 检查通过。原证书背景候选经机主批准 `adb install -r` 到一台 Android 13 平板；机主认可自由小窗、分屏和完整窗口识别，实际 Activity 标志分别为多窗口 true／true／false。只读设置诊断返回自动／有效类型均为平板（约 10.99 英寸）；新增管理员诊断和 phone／tablet／auto setter 验证通过，手机旧横屏偏好保留，最后恢复原自动选择，系统旋转设置不变。

未展开完整设备矩阵或重跑旧版全部功能测试；四方向／方向锁定的完整组合、画中画、API 36 大屏设置兼容属性及其他设备仍需后续 Beta 验证。两风味均做优化 Release 构建与最终签名包核对，不把单台结果扩大为通用兼容结论。安装不卸载、不清数据，不绕过系统限制。
