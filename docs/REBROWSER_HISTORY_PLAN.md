# ReBrowser 历史记录

历史记录在 v0.4.3-alpha 实现。本页记录机主确认的规则、当前实现和验证范围；后续可以根据实际目标调整，不把既有实现当作永久设计要求。

## 列表与入口

- 入口位于 ReBrowser 菜单的书签栏下方。
- 类似收藏夹的网址列表，按访问时间倒序排列；相同时间按记录 ID 倒序。
- 每行显示标题、完整网址、时间、来源名称和保留类型；点击在当前总标签页的当前子标签页打开，不自动恢复旧 Profile。删除单条记录需要确认。
- 原生 ListView 复用可见行，首批 50 条，可加载更早记录；分页不删除数据库中的长期记录，也没有通过数量上限自动淘汰历史。
- WebView 主页面 `doUpdateVisitedHistory` 回调记录访问，包括刷新、返回和页面自身改网址。重复访问保留为独立记录；标题回调更新对应记录，不新增一次访问。iframe 不单独生成历史。
- 只接受有效 HTTP(S) 网址，不记录 about:blank、文件、脚本或其他协议。去除网址 authority 中的用户名／密码；路径、查询和片段为恢复访问而本地保留，可能包含敏感信息。

## 保留期限：跟随整个总标签页

| 来源状态 | 未启用“维持记录”时 |
| --- | --- |
| 仍打开的副／主总标签页 | 长期保留，可手动删除 |
| 临时总标签页 | 每条新访问记录保留 30 分钟 |
| 已关闭／收起的副总标签页 | 相关历史从整个总标签页关闭时起再保留 30 分钟 |

- **关闭子标签页不删除历史，也不改变历史保留期限。** 生命周期只跟随整个总标签页。
- **副总标签页收起到书签栏视作关闭**；不因此删除书签栏的环境或 Profile 数据。
- 恢复副总标签页时，尚未到期／正在维持的历史转回长期保留；已删除或已到期的历史不恢复。
- 临时总标签页提升为副／主级别时，仍有效的历史转为长期保留。副级别降为临时时，原长期记录从转换时起获得 30 分钟过渡期，新访问仍按各自访问时间计时。
- 关闭临时总标签页不续期；删除已经收起的环境也不重新计算其历史期限。
- 沿用当前主总标签页不能直接关闭的生命周期逻辑；需要先降级再关闭。启动时也会核对来源，给已不存在的长期来源补上一次 30 分钟期限，不在每次启动时续期。
- 到期时间戳存入独立私有 SQLite。启动、记录访问、列表读取和条目操作时检查并清理；应用未运行时不承诺在到期瞬间物理删除数据库行。**没有常驻后台计时器、服务或到期任务。** 过期列表行再次点击时也会重新核对期限。

## 右上方三个圆形图标按钮

### 1. 维持记录

- 未开启为淡灰色三角形；开启为红色方块，点击结束。
- 开启期间，所有来源暂不自动到期；有限期限分类仍保留，方便结束时恢复规则。不会找回已经删除或到期的记录。
- 结束时，所有仍有时限的记录从此刻重新获得完整 30 分钟；仍属于打开副／主总标签页的历史继续长期保留。
- **开启状态跨进程重启和原地升级保存**，与期限更新同在 SQLite 事务内。
- 开启期间禁用按钮二，但仍允许逐条手动删除。

### 2. 清理有时限记录

- 带“30”字样的刷新箭头，单击执行，不是开关。
- 立即清除所有有限期限记录，包括临时来源和已关闭／收起的副来源。
- 不清除仍长期保留的历史；维持记录期间，界面和数据层都拒绝此清理动作。

### 3. 暂停历史记录

- 面具图标，开启时变为紫色选中状态，关闭时为灰色。
- 开启后不接收新记录；已有记录仍按保留规则到期，暂停不隐含冻结期限。
- **状态只保留于应用进程，不写入持久化设置**；切后台、返回、Activity 重建或模式切换不取消暂停，进程重启默认关闭。
- 用户结束暂停时，对所有仍打开的总／子标签页各补记一次当前网址和标题。后台页面运行时已销毁时，使用现有标签元数据；不包括收起环境和已关闭子页。
- 不重新加载网页，也不补录暂停期间的中间访问过程。
- 每个新进程首次进入浏览器时，为恢复的后台标签页同步当前元数据一次；前台页由实际主页面访问回调记录，避免重复同步。Activity 重建不重复进行这次启动同步。
- 面具目前只暂停历史写入，**不是完整无痕隔离模式**；Cookie、网站权限和 Profile 隔离策略不随之改变。

## 数据和管理员边界

- 历史使用应用私有 `rebrowser_history.db`，不在网站 JS 桥中提供读取接口，不共用邮件数据库，也不因清理历史删除 Cookie、Profile、收藏或邮件。
- 新增一级 `history-status` 查询和 `history` 界面路由；capabilities／diagnostics 同时包含状态快照。
- 查询仅返回开关状态、数量、保留秒数、下一到期时间及非敏感存储错误类型。`timedRecordCount` 是通常有限期限的来源分类，维持期间这些记录不自动到期；`nextExpiryAt=0` 表示当前没有自动到期时间。
- 协议结果不返回历史条目、网址、标题或网页内容；不新增管理员历史开关、删除、导出或任意 SQLite 操作。读取状态可能执行正常的过期清理，但不会更改开关。

## 验证范围

- 本轮历史功能新增 27 个 JVM 测试（包括状态同步、模拟时钟期限、生命周期转换、持久化、分页、删除、按钮行为和管理员边界）；连同桌面入口显隐，总计 80 个 JVM 测试通过，39 项 Node.js 权限脚本检查通过。
- 真机验证了实际导航写入、暂停期间三次导航不新增历史、恢复后补记全部三个打开页面且不补录中间页面、关闭子页后长期历史不变、收起整个来源后转换期限、恢复来源、维持期间禁用清理以及维持期间单条删除。
- 真机原地重新安装后，维持状态保留、暂停状态默认关闭。最终 versionCode 14 非调试 Release 包已安装，确认三个按钮可见、状态查询正常、无存储错误。
- 精确 30 分钟边界和全量临时清理主要由模拟时钟及界面测试覆盖；没有把单次真机观察当作所有网站、启动器、存储故障和生命周期组合的完整验证。

新标签页的近期访问接入、完整防护／无痕模式和更细的历史交互后续讨论，本版不提前实施。
