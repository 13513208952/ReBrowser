# ReVideo 原生移植暂停检查点

日期：2026-11-09。机主要求暂停功能开发，保存当前代码到临时分支，推送后将该分支源码 ZIP 保存到 Windows 根分区。本记录是后续接手约束，不是发行完成声明；此轮只整理记录与源码快照，不继续实现下列减法。

临时分支：`wip/revideo-native-checkpoint-20261109`，仓库 `13513208952/ReBrowser`。原工作目录是无 `.git` 的源码副本；本次从 `v1.0.5`（`1dd1735b6213532d8e3a73863748994b29280192`）恢复历史基点，再提交整个当前源码状态，不改主分支或发行标签，也不丢弃本轮之前的浏览器、GeckoView、邮件及音乐相关改动。

## 核心决策：在当前原生底座上做减法

当前已将机主提供的 pili20/PiliPlus 大部分原生源码及资源导入 `revideo/`，使用 Flutter / media_kit，并接入 ReBrowser 两种宿主。完整导入是实现底座，不代表产品要变成完整 pili20，也不代表机主取消了最初的布局精简。

恢复工作时保留原版页面、控制器、真实接口和成熟播放交互，按下表收敛当前进度。不要回退旧 Java/Gecko/dash.js 混合功能页，不再另写一套貌似原版但功能简陋的 UI。移植或复用源码已经获得机主许可；原版行为实现质量要求与产品入口数量是两回事。

## 相对原项目的额外特殊修改要求

### 界面、播放与真实操作

- 严禁擅自在用户界面加入非 pili20 原版说明性文本，包括实现方式、能力限制、演示状态、迁移说明和额外引导。确需新增时先逐条交给机主确认；代码注释、许可和开发文档不受此界面限制。
- 原版已有说明可随保留功能保留，不把“不新增说明”解释为删除正常控件、状态或原版全部说明。
- 单 P 常规视频不显示分 P 提示或选集界面；多 P 使用原版紧凑横向选集及完整选集面板，不使用裸超链接。
- 点赞、投币在收藏左边；收藏、稍后再看、点赞、投币均须是实际接口与回执状态，不能交付演示按钮。原创视频累计投币上限 2 枚，转载上限 1 枚，扣除已投数量并检查余额；遵循原版机制。
- 未登录公共 1080P 请求自动生效，无播放前二选一，也不增加免登录画质开关。以真实返回/解码轨道判断画质，不用顶层 quality 或选中标签冒称已播放 1080P。
- 不伪造账号/大会员权限、不提供 TLS 绕过、不做静默画质替换。大会员验证按机主要求暂缓。机主曾允许有把握后谨慎投币，但硬币有限，不用重复提交或不确定结果消耗余额；本次原生烟测未投币，也未进行其它真实账号写入。
- 小窗对标机主给出的原版截图：平时简洁视频画面，交互时再显示系统操作，不搬入大块控制面板。系统 PiP 的平台差异不能冒称与特定厂商外观完全一致。

### 下载仍须核对的产品约束

- 未完成文件留在应用私有空间；音视频合流、校验并取得最终可用文件后才进入已完成并发布系统媒体库。不得把下载轨道完毕当作整个任务成功。
- 普通账号自动使用实际可得的最高普通画质；大会员在同时可得 1080P 高码率与更高画质时按原约定提供选择，不显示不存在或无权限的档位。恢复任务不得悄然更换账号、画质或编码。
- 下载当前/全部需按普通 CID、分 P、UGC 合集成员及当前番剧季完整展开，不混入其它季或漏掉未加载分页。仅 UGC 合集的全部下载另行确认，已指定文案为「您确定要下载当前视频合集全部视频吗？」。
- 任务支持可靠的暂停、恢复、取消与失败重试；临时文件、授权和完成状态不能靠说明文本或“缓存”改名代替。上述约束尚未在新原生下载实现中逐项验收。

### 双宿主与数据隔离

- 下一正式版同时发行 WebView 与 GeckoView 版本，之后并行维护；允许先集中校准一版，再将另一版推进到同等质量，不能据一版通过宣称双版完成。
- 两宿主共用同一原生 ReVideo 模块；核心历史、收藏、稍后再看、订阅、账号、播放器及设置不使用网页功能页替代。必要验证码等原版辅助 WebView 不等于恢复混合核心方案。
- ReVideo 通过既有 launcher alias 进入隔离的 `:revideo` 进程与任务；关闭视频不应退出或伤及浏览器、ReOutlook、ReMusic。刷新本模块持久化数据、释放音频服务，并清理指向旧 Dart isolate 的 Java 回调。
- 默认目录、缓存、日志和下载归属 `revideo` 子目录；清理不能触碰浏览器下载、APK 安装交接、邮件或音乐缓存。必要辅助 WebView 采用独立数据目录。
- 原版账号使用本模块登录流程，不导出旧 Gecko 或 PC 审查浏览器 Cookie。既有下载、账号、浏览器数据不因换实现获得删除授权。旧 Java 下载数据库、分片与已发布文件保留，新原版格式未自动迁移旧任务。
- 移除上游独立应用自更新和会修改整个宿主默认链接设置的入口；固定快捷方式显式指向宿主 ReVideo alias。保留 JNI 所需包名与原版接口，不能为改名破坏绑定。
- 参考仓库 `/home/zhao/pilito20` 只读；修改维护副本，不修改原项目。源代码和字体许可见 [资源说明](ASSET_CREDITS.md)。

### 操作目录与资源要求

- 不再擅自修改 OMP 权限、审批或配置文件；机主已处理相关配置，牢记目录约束即可，不能重新施加过严的执行审批。
- VM SDK 系统镜像、AVD、虚拟磁盘、临时文件、日志与截图唯一获准根目录：`/run/media/zhao/Windows/android15/`；原有虚拟机不能被测试环境覆盖。
- 项目不得向主机 `/tmp` 或 `/dev/shm` 写工作文件，也不得把虚拟机镜像搬到内存。一般临时/构建文件只用 `/home/zhao/temp/reoutlook_removeable/` 或 `/run/media/zhao/Windows/tempuseforrebrowser/` 的自有子目录；一般临时目录授权不是 VM 授权。
- 显式路由 `TMPDIR`、`TMP`、`TEMP`；JVM 另设 `java.io.tmpdir` 并禁止共享性能计数临时文件。模拟器另设 `ANDROID_TMP`，ADB 另设 `ANDROID_ADB_LOG_PATH`，全部 VM 输出归唯一 VM 根。已观察到只设 TMPDIR 仍会将 SDK 崩溃日志写进 `/tmp`，现已修正并将该轮日志迁回授权根。
- 编译与模拟器不得同时运行，不得杀用户其它程序。使用现有有界串行构建入口，空间预检、运行中下限、失败停组及自有中间文件清理均保留；不要重新进行无界构建或新增一套过度资源架构。

1. 先按本记录执行入口与配置减法，保留原版成熟实现；明确综合搜索和下载的真实行为要求，不只做表面改名/隐藏。
