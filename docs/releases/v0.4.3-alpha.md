# v0.4.3-alpha

## ReOutlook 桌面入口显隐

- ReBrowser 设置新增“显示 ReOutlook 桌面入口”，默认显示，选择跨进程重启和原地升级保留。
- 只控制独立的桌面 activity alias，不禁用 MainActivity；隐藏后浏览器菜单的“切换到 ReOutlook”仍正常工作，不删除邮件或网站数据。
- 首次升级时桌面入口组件迁移到 alias；不同启动器的图标缓存刷新时机与位置可能不同。

## 历史记录

- 菜单入口位于书签栏下方。列表最新在前，可逐条删除、打开及分页加载更早记录。
- 副／主总标签页历史长期保留；临时来源每条访问保留 30 分钟；整个副总标签页关闭／收起后，相关历史再保留 30 分钟。**关闭子标签页不影响历史期限。**
- 右上角三个圆形图标：
  - 灰色三角形／红色方块：维持记录，开启期间不自动到期，跨重启保存；结束后有限期限记录重新获得完整 30 分钟。
  - 带“30”的刷新箭头：立即清除所有有时限记录；维持期间禁用。
  - 灰色／紫色面具：暂停写入；切后台不重置，进程重启默认关闭。结束暂停时，为所有仍打开的总／子标签页各补记当前网址和标题，不重新加载、不补录中间过程。
- 恢复副环境时，只将尚存且有效的历史恢复为长期保留；已删除或到期的记录不恢复。副环境降为临时时，旧长期记录获得 30 分钟过渡期。
- 使用独立私有 SQLite 和到期时间戳，读取／记录等时清理，不运行后台倒计时服务。没有以记录数量为上限自动淘汰长期历史。

**面具目前只暂停此访问列表，不是完整无痕隔离。** 标签元数据、WebView 回退栈、Cookie 和网站存储不因此清空。访问历史本地保存完整路径、查询和片段，可能含有敏感信息；网址中的用户名／密码部分移除，历史不上传给开发者。

新标签页近期访问、背景个性化、Bing 热搜及完整防护模式仍待讨论／实现，本版不提前加入。

## 管理员控制

- 协议 v2 新增一级 `launcher-status`、`history-status` 查询和 `history` 界面路由。
- capabilities／diagnostics 包含对应固定状态快照。
- 沿用 DUMP 权限、一次性挑战、原授权分级和审计；没有任意组件控制、历史明细导出或 SQLite 操作，也没有新增管理员设置这些开关的能力。

- 相比 v0.4.2-alpha 新增 34 个 JVM 检查，总计 **80 个通过，0 失败／错误**；Node.js 权限脚本 **39 项检查通过**。
- 干净 Release 构建通过；Lint **0 错误、26 警告**。
- 真机验证入口隐藏后的菜单进入邮件、跨重新安装保存和恢复显示。
- 真机验证实际导航记录、暂停期间不写入、恢复时三个打开页面同步且不补录中间页、关闭子页后长期历史不变、收起／恢复整个来源、维持期间禁用清理和允许单条删除。
- 原地重新安装后维持状态保留、暂停默认关闭；**最终 versionCode 14 非调试 Release 已安装**，三个历史按钮及状态查询正常，无存储错误。
- 精确 30 分钟边界与全量临时清理主要由模拟时钟／界面测试覆盖；未承诺所有网站、启动器、存储故障和生命周期组合均已真机验证。

## Release 优化与安装

- R8 优化、代码裁剪和混淆开启，使用 `proguard-android-optimize.txt`；没有添加宽泛保留规则或关闭优化。
- Android 资源裁剪开启；DEX ZIP 压缩开启。
- `classes.dex` 从 **302,016** 字节压缩到 **137,887** 字节。
- R8 mapping、configuration、seeds、usage 和资源报告保留在本地发布归档，不上传截图、设备日志、私钥或重复测试包。

- Android 10／API 29 起，targetSdk 36。
- `versionCode=14`，`versionName=0.4.3-alpha`，非调试 Release 包。
